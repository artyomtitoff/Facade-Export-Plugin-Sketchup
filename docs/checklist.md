# Соответствие задания и реализации

Пошаговая сверка ТЗ «Экспорт фасадов» (версия 1.5.8) с кодом.

## 0. Подготовка

| Задание | Реализация |
|---------|------------|
| Пользователь выравнивает вид перпендикулярно плоскости фасада | Направление взгляда читается из камеры (`Framing.horizontal_direction`). Если вид вертикальный (сверху/снизу) или сильно наклонён — плагин просит выровнять вид. |
| Экспортируется то, что открыто | `Framing.content_bounds`: если пользователь вошёл в группу/компонент, кадр считается по содержимому этой группы (через `model.active_path` и трансформации), а окружение временно скрывается (`Exporter#isolate_context`) и возвращается после экспорта. |
| Окно сохранения появляется сразу | `main.rb#export_facades` до диалога проверяет только камеру (`Framing.facade_directions`); `Framing.content_bounds` вызывается уже после выбора папки (`Exporter#export_bounds`, один раз за экспорт, с кэшем `@bounds`) |
| Габариты — только по видимым линиям и граням | `Framing.visible_bounds` обходит сущности «дешёвым» способом: тип определяется один раз на класс (`@kind_cache`), видимость метки — один раз на метку (`@layer_cache`), габариты видимого ребра/грани/картинки берутся готовыми (`entity.bounds`), содержимое определения считается один раз (кэш `@definition_cache`). Игнорируются: `hidden?`, объекты и геометрия со скрытых меток (`layer.visible? == false`) и меток в скрытых папках (`layer.folder.visible? == false`), направляющие и точки привязки, плоскости сечений, размеры и тексты. `entity.bounds` больше не используется. |
| Нет видимой геометрии — нет пустого кадра | `Framing.content_bounds` бросает `ExportError` с понятным текстом вместо съёмки пустого PNG |

## Автоматический вывод фасада (1.5.8)

| Требование | Реализация |
|------------|------------|
| **Готовых фасадов быть не должно — ни одного, распознавание убрано** | `AutoFacades#detect` возвращает `{:facades => [], :plan, :scope, :magnets}`: анализ собирает только схему сверху и направления главных плоскостей. Список фасадов в окне заполняется **только** тем, что пользователь нарисовал (и что лежит в файле модели). Кластеризация стен (`cluster_faces`, `split_runs`, `group_accepts?`, `depth_tolerance`) удалена целиком — её единственной оставшейся работой были магниты. |
| Ограничения на число фасадов нет | `Config::MAX_AUTO_FACADES`, `normalize_auto!(:max_facades)`, поле «Максимум нарисованных фасадов», счётчик «0 из 30» и проверка в `add_facade`/окне удалены. Тест рисует 41-й фасад. |
| Кнопка после повторного нажатия показывает нарисованное | `AutoExport.save_drawn` / `load_drawn`: список пишется в `model.set_attribute('FacadeExport', 'auto_facades', JSON)` при каждом изменении (добавили, передвинули, развернули, удалили) — поэтому линии переживают и повторное нажатие кнопки, и закрытие окна, и сохранение файла. Ключ — контекст (`path:<persistent_id/…>` для открытой группы, `model` для верхнего уровня). `AutoFacades#restore` собирает фасады обратно по линии, флагу стороны (`flip`) и номеру (`index`). |
| Хранение не должно замедлять сохранение и растить файл | В атрибутах лежит одна строка JSON на контекст: `id, index, x1..y2, flip, nx, ny, name, orient, ratio` — десятки байт на фасад. Геометрия, текстуры и определения не создаются, обсерверов нет, при сохранении файла ничего не считается. |
| Экспортируется та сторона, которую нарисовали | `build_drawn_facade`: нормаль — перпендикуляр к линии **наружу** (`#outward_normal`: сторона ближайшей параллельной стены, иначе по массе геометрии), `direction = -normal`, камера `eye = target - direction × distance` (снаружи, смотрит на стену). Сторона хранится флагом `Facade#flip`. Кнопка «⇄» (`#invert`) переключает `flip` — **сколько угодно раз**: первое нажатие разворачивает, второе возвращает исходную сторону. |
| Разворот работает не один раз, а всегда | `invert` не пересчитывает нормаль «по геометрии», а инвертирует сохранённый флаг: `facade.flip = !facade.flip`, нормаль = `±perp`. Перенос (`move`) флаг сохраняет (и не переворачивает фасад, даже если на новом месте «наружу» вышло бы иначе). Тесты проверяют три нажатия подряд. |
| Сечение — на каждый фасад, ровно на его линии, режет то, что перед линией | `#section_plane_data` **всегда** возвращает плоскость: точка `right*u_center + normal*(depth + ε)`, `ε = max(span*0.002, 0.1)` со стороны камеры, `plane_normal = facade.normal`. Всё между камерой и линией отсекается, стена и то, что за ней, остаются. `drawn_plane_data` и старое правило «сечение только если линия пересекает здание» удалены. |
| Разрез действует только на своём фасаде | `#activate`: активной делается ровно плоскость этого фасада (`active_section_plane=`), остальные наши плоскости скрыты **и выключены** (`deactivate_plane` → `active_section_plane = nil`, потому что спрятанная плоскость продолжает резать); если у фасада плоскости нет — `clear_active_planes`. |
| Пустых кадров быть не должно | Плоскость стоит на `depth + ε` (со стороны камеры), поэтому стена не попадает в саму плоскость и не исчезает; камера в 1,5 высоты кадра перед стеной. Тест проверяет, что в каждом кадре активна ровно одна плоскость и она меняется вместе с фасадом; пустая геометрия по-прежнему даёт `ExportError` с понятным текстом, а не PNG. |
| Ориентация выбирается первой, потом пропорции; **в списке нет повторов** | `Config::AUTO_ORIENTS` (`h` горизонтальное, `v` вертикальное, `sq` квадрат) и отдельные списки пропорций: `AUTO_RATIOS_H` (4:3, 3:2, 16:9, 2:1, 3:1), `AUTO_RATIOS_V` (3:4, 2:3, 9:16, 1:2, 1:3), `AUTO_RATIOS_SQ` (только 1:1; в окне список заблокирован). `Config.auto_ratios_for(orient)`, `auto_default_ratio(orient)`, `auto_ratio(name, orient)`, `auto_ratio_name(name, orient)` — пара чужой ориентации заменяется на первую своей. `AutoFacades.image_size` — длинная сторона из настроек экспорта, вторая по паре: `h 4:3 → 9999×7499`, `v 3:4 → 7499×9999`, `16:9 → 9999×5624`, `9:16 → 5624×9999`, `sq → 9999×9999`. |
| По умолчанию — горизонтальное 4:3 | `Config::AUTO_DEFAULT_ORIENT = 'h'`, `AUTO_DEFAULT_RATIO = '4:3'` (плюс `AUTO_DEFAULT_RATIO_V = '3:4'`, `_SQ = '1:1'`); `default_auto`, `normalize_auto!`, вкладка настроек и окно вывода берут эти значения. Режим «авто — по фасаду» удалён (`AUTO_RATIO_AUTO` больше нет), единый `aspect` и `min_area` тоже. |
| Линия магнитится к главным плоскостям модели — **и сильнее, и во время протяжки** | `#magnet_directions`: направления стен группируются по `ANGLE_TOL = 12°` со взвешиванием по площади, в магнит попадают только группы с площадью ≥ 10 % (`MAGNET_SHARE`) от самой крупной — мелкие элементы под своим углом магнит не создают. Допуск `SNAP_TOL = 14°` (было 10°). Окно получает те же направления (`magnets` + `magnetTol`) и притягивает линию **прямо во время протяжки**, с тем же допуском и поворотом вокруг середины, — магнит видно до отпускания кнопки. |
| Линию можно двигать, но не поворачивать | Окно: протяжка по линии (`lineAt`, `moving`) переносит оба конца (`translateSegment`) и отправляет `sketchup.move_facade`; `AutoFacades#move` строит фасад по новой линии, сохраняя сторону (`invert`, если авто-нормаль смотрит в другую сторону), имя, номер и пропорции. Поворот невозможен: направление берётся из старого фасада. |
| Стрелка — только треугольник, со стороны камеры, смотрит на линию | `arrowMark` в `auto.html`: `<path>` из трёх точек, древка нет; носок в 8 px от линии, высота 30, полуширина 15. Треугольник стоит по `+normal` — там же, где камера, — и смотрит на линию, то есть туда же, куда смотрит камера фасада. |
| Кружки крупнее, ближе к линии, линия тоньше | Номер: `r = 23`, шрифт 24 полужирный, отступ от линии 42 px (было 150–350 px «кольцами» снаружи контура), при нехватке места — сдвиг вдоль линии, затем чуть дальше; минимальный зазор между кружками 62 px. Линия фасада 10 px у выбранного и 7 px у выключенного (было 14/10), протягиваемая — 12/10. Кружок ставится с противоположной стрелке стороны. |
| Нумерация = имя, с 1, первый свободный номер | `#next_free_index(facades)` — самый маленький неиспользованный номер, `#assign_numbers!(facades)` сохраняет уже выданные номера и переименовывает только «Фасад N». Вызывается после добавления, переноса, разворота, удаления и при восстановлении из файла, поэтому после удаления номера **не переезжают**, а новый фасад занимает освободившийся. Первый нарисованный фасад всегда «Фасад 1». Окно после удаления получает полный набор (`Dialogs.push_auto_data_public` → `AutoExport.refresh_payload`). |
| Быстро: линия, разворот и перенос без задержек | При анализе у каждой записи один раз кэшируются `v_min`/`v_max` (`bounds_span_z`), поэтому `drawn_extents` больше не перебирает вершины граней при каждом движении линии (тест `Face#vertex_calls` = 0). Кластеризация стен, работавшая при открытии окна, удалена. |
| Курсор «перетащить» над линией | `setHover` в `auto.html`: при наведении на линию у схемы класс `draggable` (`cursor: grab`), при протяжке — `grabbing`, иначе `crosshair`. |
| Можно разворачивать и удалять фасады | «⇄» → `sketchup.invert_facade` → `AutoExport.invert_facade` → `AutoFacades#invert` (та же линия, противоположная нормаль, имя сцены по новому румбу) → `updateFacade`. «×» → `sketchup.delete_facade` → `AutoExport.remove_facade` (перенумерация + сохранение в модели + перерисовка окна). |
| Анализ идёт там, где пользователь работает, камера не важна | `#collect_faces`: пустой `model.active_path` → `model.entities` (`scope = :model`), иначе `path.last.definition.entities` (`scope = :context`) с накоплением трансформаций. Камера при поиске не читается. |
| Кнопка открывает окно мгновенно | В `detect` читаются только `normal`, `area`, `bounds` грани; вершины не перебираются (тест `Face#vertex_calls`), превью фасадов нет вовсе. |
| Схема сверху совпадает с реальным зданием | `plan_map` собирает контур из граней, **смотрящих вверх** (`collect_plan_face`, `PLAN_FACE_Z = 0.7`, `plan_loop`, `simplify_polygon`), окно рисует их `<polygon fill="#d6dae1">` без обводки — силуэт с косыми крыльями и двором читается сразу. Клетки сетки остались запасным вариантом. |
| Схема условная: без деталей и балконов | В окно уходят только полигоны/клетки схемы в координатах 0..1000; реальная геометрия не передаётся. |
| Фасады не обязаны стоять под 90° | Направления стен группируются по нормали с допуском `ANGLE_TOL = 12°`, магнит берётся из этих групп — повёрнутое на 30° здание магнитит линию к своим стенам, а не к осям. |
| Внутренние фасады двора тоже нужны | Сторона фасада определяется ближайшей параллельной стеной (`outward_normal`), поэтому линия во дворе снимает двор, а не наружную стену; сторону всегда можно развернуть «⇄». |
| Сначала папка, потом вся тяжёлая работа | `AutoExport.export`: `apply_selection` → `Dialogs.ask_destination` → подтверждение перезаписи → `build_cameras!` → плоскости → `Exporter#run`. Тесты фиксируют, что в момент окна сохранения ни камер, ни плоскостей ещё нет. |
| Экспорт обязан записать файлы и показать отчёт | `Exporter#run` вызывается в `begin/ensure`; отчёт (`Dialogs.show_report`) или сообщение об ошибке показываются при любом исходе, даже при исключении. Сбой внутри колбэка окна тоже показывается пользователю. |
| Вид после экспорта — точно как до нажатия | `AutoFacades#snapshot_camera`/`#restore_camera` плюс `SceneState` внутри `Exporter#run`; восстановление выполняется в `ensure`, поэтому работает и при сбое. |
| Сцены по умолчанию временные | `auto.delete_scenes = true`: сцены не создаются, пока их не оставляют. `#cleanup!` удаляет сцены и плоскости и возвращает видимость/активность плоскостей пользователя и камеру. `create_scenes!` — только если сцены оставляют. |
| Экспорт режет даже при выключенных у пользователя разрезах | `Exporter#auto_cuts?` → `DisplaySectionCuts = true` для прогона с авто-фасадами; рамки плоскостей (`DisplaySectionPlanes`) всегда `false`. |
| Чужие секущие плоскости не должны резать модель | `#suspend_foreign_planes` перед съёмкой (контекст каждой активной чужой плоскости переводится в `active_section_plane = nil`), `#resume_foreign_planes` возвращает активность после. |
| Экспортируется только то, что в группе | `Exporter#isolate_context` скрывает всё вне открытой группы до съёмки, `restore_isolation` возвращает после. |
| Имя каждого фасада редактируется | Поле «Имя фасада» в окне → `AutoExport#apply_selection`; имя идёт в название сцены и в имя файла: `Префикс_Имя_Карта.png` (`Exporter.file_name`). |
| Общий масштаб и прижатие к низу кадра | `#build_cameras!`: масштаб = минимум по выбранным фасадам, `target.z = v_min + (H/2 − gap)/scale`, камера параллельная. |
| Своя вкладка настроек | `html/settings.html` → вкладка **«Авто-фасады»**: ориентация кадра по умолчанию, пропорции кадра по умолчанию, начало имени сцены, «создавать сцены», «удалять сцены после экспорта», «подрезать сечением». Список пропорций подстраивается под ориентацию, у «квадрата» единственная 1:1. `min_area`, `max_facades` и единый `aspect` убраны (`Config.default_auto`, `Settings#normalize_auto!`). |

## 1. Общий стиль для всего экспорта

| Требование | Ключ / метод |
|------------|--------------|
| Вид → скрыть направляющие | `HideConstructionGeometry = true` |
| Правка → Фон → убрать небо и землю | `DrawSky = false`, `DrawGround = false`, `DrawHorizon = false` |
| Фон RGB 255,255,255 | `BackgroundColor`, `SkyColor`, `GroundColor` = `Color(255,255,255)` |
| Правка → Край → убрать профили, показ глубин, расширение, конечные точки, дрожание, пунктир | `DrawProfilesOnly`, `DrawDepthQue`, `ExtendLines`, `DrawLineEnds`, `JitterEdges`, `DisplayLineStyles` = `false` (дополнительно `DrawSilhouettes = false`, `EdgeType = 0`) |
| Правка → Грань → убрать задние рёбра и рентген | `DrawBackEdges = false`, `ModelTransparency = false` |
| Тени → убрать «Использовать солнце для затенения» | `UseSunForAllShading = false` (галочка есть только на вкладке «Экспорт» в расширенных настройках) |
| Камера → параллельная проекция | `camera.perspective = false` — **включена по умолчанию** (`export.projection = 'parallel'`) |

Дополнительно (чтобы в кадр не попадала служебная графика): `DrawHidden = false`,
`DisplaySketchAxes = false`, `DisplayInstanceAxes = false`, `DisplayText = false`,
`DisplayDims = false`, `DisplaySectionPlanes = false`, `DisplayWatermarks = false`,
`DisplayFog = false`, `ShowViewName = false`, а также снимается выделение.
Эти параметры не настраиваются — служебная графика не рисуется всегда
(настройки `hide_guides`, `hide_annotations`, `show_section_planes` удалены).

Небо и земля скрываются настройками **«Скрывать небо»** и **«Скрывать землю»**
(`export.hide_sky`, `export.hide_ground`), обе включены по умолчанию;
старые ключи `show_sky`/`show_ground` переносятся в `Settings#normalize!`.

## 2. Кадр и автоматическое масштабирование

| Требование | Реализация |
|------------|------------|
| Кадр 4:3 (по умолчанию) | `Config::DEFAULT_ASPECT = '4:3'`, `Framing.image_size`: 9999 × 7499 |
| Соотношения: 4:3, 3:2, 16:9, 2:1, 3:1, 1:1 | `Config::ASPECTS` — только «широкие» варианты; вертикальные (3:4, 2:3, 9:16) убраны, потому что кадр разворачивается автоматически |
| Режим «только видимый участок» (по умолчанию выключен) | `export.visible_area` → `Framing.visible_cameras`: камера пользователя без подгонки, **соотношение сторон и размеры из настроек** (`Framing.visible_image_size`), остальные фасады — поворот на 90° вокруг цели, отступ не применяется |
| Перспективный вид переключается до экспорта | `Exporter#switch_to_parallel_view` + `Framing.parallel_camera`: вид переводится в параллельную проекцию (та же точка взгляда, цель и направление, высота кадра эквивалентна перспективе) **до** расчёта кадров и съёмки; камера пользователя возвращается в `ensure` |
| Размер PNG не зависит от формы окна просмотра | `Framing.visible_image_size` использует `export.aspect` и `export.width`, `view.vpwidth/vpheight` в расчёте не участвуют |
| Большая сторона 9999 px | `export.width = 9999` — длина **большей** стороны кадра |
| Высотные объекты | `Framing.content_vertical?` — если самый большой фасад выше, чем шире, кадр разворачивается: 7499 × 9999 |
| Самый большой фасад задаёт масштаб | `Framing.biggest_index` + `Framing.pixels_per_unit` (минимум по всем четырём направлениям) |
| Фасад прижат к низу кадра | `Framing.build_camera`: `target.z = v_min + (H/2 − gap)/scale`, горизонтальное центрирование |
| Отступ вокруг фасада | `export.margin` (0,02) → `Framing.gap_pixels` |
| Размер не зависит от окна просмотра | `View#write_image` всегда получает явные `:width` и `:height` |
| Масштаб одинаковый у всех фасадов | Одна и та же `camera.height` у всех четырёх камер |
| Настройки «масштаб по каждому фасаду» нет | Такой опции нет ни в коде, ни в окне настроек (по решению пользователя) |
| Экспорт одного фасада с подгонкой по всем (по умолчанию выключен) | `export.fit_all_facades` → `Exporter#build_cameras`: при `facade_count == 1` и включённой опции считаются проекции всех четырёх направлений, масштаб берётся по самому большому фасаду, снимается только текущий вид — кадр совпадает с полным экспортом |

## 3. Карты

### 3.1 Текстура

| Требование | Реализация |
|------------|------------|
| Правка → Грань → «Затенение с текстурами» | `RenderMode = 2`, `Texture = true` |
| Прозрачность материала убрать | `MaterialTransparency = false` |
| Правка → Край → скрыть края | `EdgeDisplayMode = 0` |
| Стеклянные ограждения исчезают | `GlassRecolor` в режиме `hide_railings`: непрозрачность 0 % + `MaterialTransparency = true` |

### 3.2 Линии

| Требование | Реализация |
|------------|------------|
| Правка → Край → показать края | `EdgeDisplayMode = 1` |
| Правка → Грань → «Скрытые линии» | `RenderMode = 1` |
| Ограждения исчезают | То же, что и на карте текстур |

### 3.3 Тени

| Требование | Реализация |
|------------|------------|
| Правка → Край → скрыть края | `EdgeDisplayMode = 0` |
| Тени по принципу Elevation 45 Shadows (left) | `Sun.setup`: подмена геолокации/времени, подбор `NorthAngle` и `Latitude` по фактическому `SunDirection`; резерв — оригинальная формула TIG (`Sun.legacy_north_angle`) |
| «Светлее» 100, «Темнее» 0 | `ShadowInfo['Light'] = 100`, `['Dark'] = 0`; задаются на вкладке карты («Расширенные настройки → Солнце и тени») |
| «Использовать солнце для затенения» не включается | `UseSunForAllShading = false` на каждом шаге |
| Грани белые, чтобы остались только тени | `RenderMode = 1` |
| Ограждения исчезают | Режим `hide_railings` |

### 3.4 Окна и типы стекла

| Требование | Реализация |
|------------|------------|
| Отключить тени | `DisplayShadows = false` |
| Правка → Грань → «Отобразить в режиме теней» | `RenderMode = 2` |
| 0–10 % — стеклянные ограждения | `Config::GLASS_RAILING_MAX = 10`; H 300 / S 100 / L 50, на карте окон непрозрачность 100 % |
| 11–89 % — основное стекло | H 125 / S 100 / L 50 |
| 90–99 % — тонированное стекло | `Config::GLASS_TINTED_MIN = 90`; H 180 / S 100 / L 50 |
| ≥ 99,5 % — обычный материал | `Config::GLASS_OPAQUE_MIN`, материал не трогается |
| Ограждения невидимы на картах текстур/линий/теней | Режим `hide_railings` (непрозрачность 0 %) |
| На карте окон непрозрачные текстуры белые | `GlassRecolor.scan(:include_opaque)` находит материалы с непрозрачностью ≥ 99,5 % и текстурой; при `:whiten_opaque` (только карта `kind = 'windows'`) действие `:white` убирает текстуру и ставит цвет 255/255/255, `restore` возвращает и то и другое |
| Основное и тонированное стекло на этих картах непрозрачны | Тот же режим `hide_railings`, действие `:opaque`: цвет и текстура сохраняются, `alpha = 1.0` — фасад не просвечивает и принимает тени |
| Галочка «Разделять карты окон по типам стекла» (по умолчанию выключена) | `maps.windows.split_windows` → `Exporter.output_jobs`: три карты «окно-стекло», «окно-тонировка», «окно-ограждения» (`Config::GLASS_TITLES`) |
| Возврат цветов | `GlassRecolor#restore` (цвет + альфа + путь к текстуре) |

## 10. Возврат настроек

| Требование | Реализация |
|------------|------------|
| Вернуть всё как в п. 0 | `SceneState`: снимок `rendering_options`, `shadow_info` и камеры до начала работы, восстановление в `ensure` (работает и при ошибке); выделение, видимость окружения и строка состояния тоже возвращаются |
| В журнале «Отменить» нет шагов экспорта | `Exporter#begin_export_operation` / `#end_export_operation`: `start_operation('Экспорт фасадов', true)` перед работой и `abort_operation` в `ensure`. Скрытие окружения, непрозрачность материалов и цвет стекла откатываются вместе со служебной операцией, история пользователя не тратится |

## Сечения

| Требование | Реализация |
|------------|------------|
| Сечения режут ровно так же, как на экране | `Exporter#section_cuts?`: `DisplaySectionCuts` = текущее значение пользователя, но только если в модели есть **активная** плоскость сечения (`Exporter#active_section_planes?`, проверяются и плоскости внутри групп/компонентов). Нет активных плоскостей или разрезы выключены — `false`, модель целая |
| Выключенные сечения не включаются | Никакой безусловной установки `DisplaySectionCuts = true` больше нет; настройки в интерфейсе тоже нет |
| Скрыть отображение сечений | `DisplaySectionPlanes = false` — всегда, настройки больше нет |
| Сечения не растягивают кадр | `Sketchup::SectionPlane` входит в `Framing::ANNOTATION_CLASSES` |

## Имена файлов

| Требование | Реализация |
|------------|------------|
| Префикс — то, что вписал пользователь в окне сохранения | `Dialogs.ask_destination`: имя из `UI.savepanel` становится `base_name` |
| Шаблон | `Префикс_Фасад_Номер_Карта.png` (`Exporter.file_name`) |
| Спрашивать только путь сохранения | `UI.savepanel` один раз; настройки применяются ко всем изображениям |
| Файл не «занят» после записи | `Exporter#write_image`: кадр пишется во временную папку (`Dir.mktmpdir`, запасной вариант — `.facade_export_tmp` рядом с результатом), затем `#publish` копирует байты в папку пользователя и сразу закрывает файл; временная папка убирается в `ensure` (`#cleanup_temp_dir`). Проводник не видит недописанных `.png`, а готовый файл не держит ни SketchUp, ни COM Surrogate |

## Главное: работа «за кадром»

| Требование | Реализация |
|------------|------------|
| Пользователь не видит промежуточных состояний, не нагружается процессор | Все изображения пишутся через `View#write_image` (рендер в память, окно просмотра не меняет размер); Ruby не отдаёт управление до конца операции, поэтому SketchUp не перерисовывает вид; после экспорта камера, стиль и тени возвращаются |
| Максимально быстрая работа | (1) без перерисовок вьюпорта и без `zoom_extents`; (2) стиль меняется только по отличающимся ключам (`OptionBag#apply`); (3) настройки солнца калибруются за несколько итераций; (4) материалы перекрашиваются один раз на карту, а не на каждый фасад; (5) изображения пишутся без сглаживания; (6) `File.delete` перед записью — без диалогов подтверждения; (7) список стекла (`GlassRecolor.scan`) считается один раз на весь экспорт и кэшируется — карта окон без стекла ничего не перебирает; (8) для режимов «непрозрачным»/«скрыть» сохраняется только непрозрачность, текстуры читаются лишь при перекраске; (9) габариты определений кэшируются, классы-аннотации ищутся один раз |

| Вкладка «Экспорт»: ширина, высота, множитель линий, отступ, возврат вида/стиля, отчёт, подгонка одиночного фасада, «только видимый участок» | Видимых полей ровно восемь; остальное — в «Расширенных настройках» |

| «Скрывать небо» / «Скрывать землю» вместо «Оставлять…» | `export.hide_sky` / `export.hide_ground`, обе включены по умолчанию; пояснения в интерфейсе нет |

| Строки «светлее/темнее задаются на вкладке карты» на вкладке «Экспорт» нет | Подсказка удалена; сами поля остаются на вкладках карт при включённых тенях |
| Вкладка карты: название, режим, «экспортировать», края, тени, прозрачность материала | Ровно шесть полей, расширенных настроек на вкладках карт нет |
| Настройки теней показываются только при включённом флажке «Тени» | Блок `data-dep="shadows"` в `settings.html`; JS `updateDeps` прячет/показывает его по флажку своей карты |
| Настройки «Текстуры» нет — берутся из режима отображения | `Config.textures_for(render_mode)`: только «Затенение» даёт текстуры; в UI поля нет, экспортёр считает значение сам (`MapOptions.textures?`) |
| «Прозрачность материала» — в основных настройках карты | Поле `material_transparency` вынесено из расширенных настроек |
| У карты «Окна» блок «Настройки отображения окон» | Разделение по типам стекла + цвета H/S/L трёх типов |
| Своя карта: полный набор, включая окна и стекло | Название, режим, края, тени (+ блок теней), прозрачность материала, «Окна и стекло»: `glass_highlight`, `split_windows`, цвета трёх типов |
| Нижняя панель не «ужимается» | `body { height:100vh; overflow:hidden }`, `main { flex:1 1 auto; min-height:0; overflow-y:auto }`, `footer { flex:0 0 auto; min-height:56px }` |
| Двухколоночные сетки: поля не соприкасаются | `column-gap: 44px`, `row-gap: 14px` в `.grid` |
| Своя карта: стекло по умолчанию не красит | `Config.new_custom_map` → `glass_highlight = false`; карта «Окна» — всегда `true` |
| Раздельные карты стекла у своей карты | Названия `Своя карта N — окно-стекло` и т.д. (`MapOptions.glass_title`) |
| «По заданию» → «по умолчанию» | Формулировка исправлена во всём интерфейсе |
| Светлее/темнее — на вкладках карт | На вкладке «Экспорт» их нет |
| «Использовать солнце для затенения» — только на вкладке «Экспорт» | На вкладках карт этой галочки нет |
| Максимум в подсказке — 9999 px | Подсказка и `max` поля ширины |
| Своя карта по кнопке «+» | Полностью редактируемая карта, экспортируется вместе с остальными, удаляется кнопкой «Удалить карту» |
| Значения по умолчанию как в задании | `Config.default_settings` (проверяется тестами) |
